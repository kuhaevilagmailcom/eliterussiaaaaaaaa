# MGN VPN

Telegram VPN-сервис с ботом, Mini App, персональными subscription-ссылками и H1Cloud/H1Panel. SQLite работает в WAL-режиме, критические начисления защищены транзакциями и идемпотентными идентификаторами платежей.

## Тарифы

| Период | Цена |
|---|---:|
| 1 месяц | 70 ₽ |
| 3 месяца | 170 ₽ |
| 6 месяцев | 370 ₽ |
| 1 год | 777 ₽ |

В каждый тариф входят два устройства. Дополнительный слот стоит 50 ₽; лимит — до пяти устройств.

## Возможности

- оплата через СБП/RollyPay и Telegram Stars с серверной проверкой суммы, валюты, покупателя, получателя и продукта;
- подарок подписки другому пользователю;
- реферальная награда до трёх дней за трёх новых пользователей;
- реферальная программа: один подтверждённый новый пользователь даёт один день, максимум три дня;
- промокоды двух типов: скидка на выбранные тарифы и бесплатные дни;
- персональная стабильная ссылка `/sub/{token}` с проксированием H1 subscription;
- частичная H1Cloud federation: отказ удалённой ноды не отменяет успешную выдачу на основной;
- импорт в Hiddify по официальной URI-схеме; для остальных клиентов показываются копирование ссылки и официальный источник загрузки;
- Mini App с проверкой Telegram `initData`, TTL и подписи;
- роли администратора, выдача дней и управление лимитом устройств;
- custom emoji из `NewsEmoji` с Unicode fallback.

## Запуск

Требуется Python 3.12+.

```bash
python -m venv .venv
python -m pip install -r requirements.txt
python main.py
```

Скопируйте `.env.example` в локальный `.env` и заполните значения. `.env` не хранится в Git.

Ключевые переменные: `BOT_TOKEN`, `ADMIN_IDS`, `DB_PATH`, `VPN_MODE=h1cloud`, `H1_API_URL`, `H1_API_TOKEN`, `H1_SUBSCRIPTION_TEMPLATE`, параметры `ROLLYPAY_*` и `EMOJI_PACKS=NewsEmoji`. Публичные адреса Mini App и subscription закреплены за `mgnvpn.ru` и не берутся из окружения.

Для production MGN VPN основным узлом должна быть **Финляндия**: `H1_API_URL` должен указывать на API панели H1Cloud именно в Финляндии. Старый API-адрес Нидерландов после удаления этого сервера использовать нельзя — приложение остановится с понятной ошибкой конфигурации. Остальные активные локации загружаются из H1 federation и текущей aggregate-подписки; Нидерланды исключены из выдаваемых конфигураций.

Не включайте реальные токены в `.env.example`, логи или репозиторий.

### Хранение данных на Bothost

В Docker/Bothost SQLite всегда приводится к постоянному хранилищу `/app/data`.
Рекомендуемый путь: `DB_PATH=/app/data/mgn_vpn.sqlite3`. Если переменная не задана
или по ошибке указывает на относительный путь / файл в `/app`, приложение автоматически
использует `/app/data/<имя файла>`. При первом запуске оно также пытается перенести
старую локальную `/app/mgn_vpn.sqlite3`, а затем хранит до пяти ротационных резервных
копий в `/app/data/backups`. Git-deploy не должен очищать пользователей, подписки,
платежи, промокоды, рефералов и настройки администратора.

## Структура

- `catalog.py` — единый каталог тарифов, цены, выгода и ограничения;
- `db.py` — SQLite-схема, транзакции, промокоды, рефералы и платежи;
- `handlers.py` — Telegram UX и платежные события;
- `miniapp.py` — API Mini App, subscription proxy и проверка `initData`;
- `vpn.py` — провайдеры и capability-модель;
- `vpn_clients.py` — проверенный реестр VPN-клиентов;
- `miniapp/web/` — мобильный интерфейс Mini App.

Ошибки `node_login_failed`, HTTP 401 и 502 отдельных remote-нод относятся к инфраструктуре H1Cloud. Приложение изолирует такие сбои, логирует ноду без персональных токенов и продолжает работу с доступными локациями.


## Скорость и диагностика H1/VPS

**Скорость VPN-туннеля определяют VPS, маршрут пользователя до страны,
качество сети, потери пакетов, загрузка CPU/канала и конфигурация Xray.**
Невозможно повысить пропускную способность VPN одной настройкой Mini App.

Обновление H1 оптимизирует *скорость импорта/обновления подписки*:
одновременные холодные запросы одной подписки используют один запрос
к H1. Исключена сортировка серверов по RTT BotHost: задержка от BotHost
не равна задержке пользователя, а TCP connect не проверяет Mbps.
Список узлов не обрезается по единичной сетевой ошибке.
В Happ следует сравнить задержки и реальную скорость каждой страны
со своего устройства, затем выбрать лучший сервер вручную.

Для **каждого** Linux-сервера с установленным H1/Xray (не BotHost)
запустите из репозитория:

```bash
bash scripts/h1_speed_audit.sh --report
```

Отчёт только читает загрузку CPU, память, сетевой интерфейс, TCP
и поддерживаемые алгоритмы. Если узкое место — TCP-передача через
загруженный/дальний канал и ядро поддерживает BBR, можно
**после замера исходной скорости** отдельно протестировать:

```bash
sudo bash scripts/h1_speed_audit.sh --enable-bbr
```

Скрипт сохраняет старые параметры и меняет только
`net.ipv4.tcp_congestion_control` и `net.core.default_qdisc`.
Ни firewall, ни Xray, ни Reality, ни SSH он не перенастраивает.
BBR не гарантирует выигрыш: при ухудшении задержек/скорости отмените:

```bash
sudo bash scripts/h1_speed_audit.sh --rollback-bbr
```

Если даже после BBR загрузка/скорость низкая, нужен замер
из сети клиента и с VPS: трасса и потери, реальная пропускная
способность VPS, CPU steal, ограничения тарифа провайдера.
Сначала устраните узкое место, затем оценивайте покупку новых нод.

## Рассылка NFT-поста через MGN VPN

Владелец или администратор с полным доступом открывает `/admin` → **🎁 NFT из поста**.
Перешлите туда **пост из Telegram-канала** (не скрывая источник). Бот покажет
копию поста с новой inline-кнопкой **🎟 Участвовать в розыгрыше**.
Кнопка ведёт в `https://t.me/AnonChatMgn_Bot?start=nft`.
После нажатия **✅ Начать рассылку** пост отправляется пользователям
бота MGN VPN: текст и фото/видео копируются, кнопка добавляется к каждой копии.
До подтверждения никаких сообщений пользователям не уходит.

При отправке бот показывает количество получателей и кнопку остановки.
После завершения инициатору приходит отчёт: доставлено, не доставлено
и отправки без подтверждения после аварийного прерывания. Рассылка работает
в фоне, состояние сохраняется в SQLite, после перезапуска отправка продолжается.
Прогресс записывается **до** запроса к Telegram, чтобы не слать дубликат после
сбоя; у одного адресата после сбоя отправка может оказаться неподтверждённой.
Повторно рассылать тот же исходный пост нельзя. Параллельных NFT-рассылок нет.

Необязательная настройка: `NFT_RAFFLE_BOT_USERNAME=AnonChatMgn_Bot` (без @).
VPN-бот не продаёт билеты и не выбирает победителя: ссылка ведёт в отдельный бот.
